## 4. 新 strict 选项详解

### 4.1 `noPropertyAccessFromIndexSignature: true`

**作用**：禁止 `obj.key` 当 obj 是 `Record<K, V>` 时（key 不在已知属性列表中）。必须用 `obj['key']`。

**影响范围**：所有使用 `Record<string, T>` / `Record<K, T>` 的地方。**预期错数**：30-80。

**示例**：
```ts
const meta: Record<string, string> = { name: 'foo' }
const n = meta.name  // ❌ 错: Property 'name' comes from an index signature
const n2 = meta['name']  // ✅ OK
```

### 4.2 `noFallthroughCasesInSwitch: true`

**作用**：switch case 结尾必须有 `break` / `return` / `throw`，否则报错。

**影响范围**：所有 switch 语句。**预期错数**：5-15。

**示例**：
```ts
switch (x) {
  case 1:
    foo()
    // ❌ 缺 break
  case 2:
    bar()
    break
}
```

### 4.3 `noImplicitReturns: true`

**作用**：函数所有返回路径必须显式 return。

**影响范围**：含 if/else 分支且部分分支 return 的函数。**预期错数**：10-30。

**示例**：
```ts
function f(x: number) {
  if (x > 0) return x
  // ❌ 缺 else 分支 return
}
```

## 5. fix-strict.mjs v2 增强

### 5.1 新增 3 类模式

| # | 模式 | 例子 | 修复策略 |
|---|------|------|----------|
| E | `obj.key` 当 obj 是 `Record<K, V>` | `meta.name` | 改 `meta['name']` |
| F | switch case 缺 break | case 后无 break/return | 在 case 末尾加 `break` |
| G | 函数 if/else 缺 return | 部分分支 return | 在缺 return 分支加 `return undefined` 或 `return null` |

### 5.2 保守模式

- E 类：只在 `obj` 是 `Record<K, V>` 类型注解时改（heuristic：识别 `: Record<` 或 `: { [key: string]:`）
- F 类：只在 case 体内无 break/return/throw 时加
- G 类：只在 if/else if/else 分支有部分 return 时加

### 5.3 新增 3 个测试

```ts
describe('fix-strict v2', () => {
  it('模式 E: obj.key → obj["key"]', ...)
  it('模式 F: switch case 缺 break 加 break', ...)
  it('模式 G: if 分支缺 return 加 return', ...)
})
```

## 10. 风险与缓解

| 风险 | 缓解 |
|------|------|
| E 类识别 Record 类型不准确 | 用 conservative heuristic（只匹配 `: Record<` 或 `: { [`）+ 留 FIXME |
| F 类改坏 switch 逻辑（共用 case 是合法的） | 不自动改，标记 FIXME 手工 review |
| G 类改坏 else 分支 | 加 return 后跑测试验证 |
| `noImplicitReturns` 误报（如 throw 函数） | throw/never 返回类型不算错（TS 自动识别） |
| 改 .vue template 类型 | 不在范围内，模板用 `as` |
