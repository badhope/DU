## 4. 新 strict 选项详解

### 4.1 `useUnknownInCatchVariables: true`

**作用**：`catch (e)` 中 `e` 类型从 `any` 改为 `unknown`，强制类型守卫后才能使用。

**影响范围**：所有 catch 块。**预期错数**：0-3（项目所有 catch 已用 `_e` 占位不读 error）。

**示例**：
```ts
try { ... } catch (e) {
  console.log(e.message)  // ❌ 错: Object is of type 'unknown'
  if (e instanceof Error) console.log(e.message)  // ✅ OK
}
```

### 4.2 `noImplicitThis: true`

**作用**：`this` 必须有类型注解（函数无类型 this 时报错）。

**影响范围**：使用 `this` 但函数无 `this: T` 注解。**预期错数**：0-5（项目以 setup script + arrow function 为主）。

**示例**：
```ts
function f() { return this.x }  // ❌ 错: 'this' implicitly has type 'any'
function f(this: { x: number }) { return this.x }  // ✅ OK
```

### 4.3 `strictBindCallApply: true`

**作用**：`bind` / `call` / `apply` 的参数类型必须与函数签名匹配（不再宽容 any）。

**影响范围**：使用 `fn.bind` / `fn.call` / `fn.apply` 的地方。**预期错数**：0-2。

### 4.4 `strictPropertyInitialization: true`

**作用**：class 属性必须初始化或加 `!` 声明 definite assignment assertion。

**影响范围**：含非初始化属性的 class。**预期错数**：3-10（Pinia store / util class 等）。

**示例**：
```ts
class Foo {
  x: number  // ❌ 错: Property 'x' has no initializer
  y!: number  // ✅ OK
  z: number = 0  // ✅ OK
  constructor(x: number) { this.x = x }  // ✅ OK
}
```

2. 逐个手工修：
   - TS2722（class 属性）：加 `!` 或初始化
   - TS18046（unknown）：加 `instanceof` 守卫
   - TS2683（this）：加 `this: T` 注解
   - TS2345（bind/call/apply）：调整参数类型
3. 跑 `pnpm type-check` 验证 0 错
4. Commit

如果某 Task 错数 > 20，拆分到单文件。

## 8. 风险与缓解

| 风险 | 缓解 |
|------|------|
| `strictPropertyInitialization` 误报（如 class 内部辅助函数） | 加 `!` 即可 |
| `useUnknownInCatchVariables` 让 catch 块变繁琐 | 项目 catch 已用 `_e` 忽略，影响极小 |
| `noImplicitThis` 误报（callback this） | 改用 arrow function 即可 |
| `strictBindCallApply` 改函数签名影响调用方 | 不重构函数，仅调整调用处的类型 |
